== Context

Tool: https://autokorrektur.org/ (the AutoKorrektur project website).
Goal (from scenario): Frank wants to get the app onto his phone from the website, and wants to know before he starts whether this is finished software he can rely on or something that might break. Success means he can download the APK and, in his own words, say (a) what he has to do next to install it and (b) how finished the software is.
How run: Mobile viewport 375x812 (Android portrait), German system language assumed, page read top to bottom in viewport-sized chunks rather than all at once, matching how a rushed novice actually scrolls. Positions below are measured in screenfuls (element top ÷ 812px viewport height).

Methodology note: direct click automation on this page consistently hung in this tool session (confirmed on an unrelated in-page link, not only the download link), so several "clicks" were reproduced via direct navigation to the same href the link points to, and the download button's behaviour was confirmed by inspecting the network log for the request it fires. This is a limitation of the test tooling, not a finding about the site, and is called out explicitly wherever it applies.

- Delight: the crash-risk warning ("Früher Testbuild: Abstürze sind möglich...") sits in the same first screen as the download button (0 screenfuls below it), directly answering the regression concern about a warning once buried far below the fold.
- Delight: the install instructions ("Installieren („Sideloading")": Datei herunterladen, antippen, dem Browser erlauben...") are phrased entirely in plain, actionable German. The technical word "Sideloading" appears once as an aside label, not as something Frank has to understand to follow the steps — a novice could repeat these steps back correctly.

- Low: the checksum/apksigner verification block is unavoidably technical (by nature), but it does not block the novice path — it sits after the plain-language install instructions, so a rushed reader simply scrolls past it without needing it.
- Low: the "4 GB RAM empfehlenswert" note gives Frank no way to check his own phone's RAM from the page, though the soft phrasing ("empfehlenswert", "rechnen länger") means it doesn't block or worry him.
- No cookie/consent banner was encountered anywhere on the page.
- Methodology note (not a site finding): click automation hung consistently in this tool session, on both the download link and an unrelated plain navigation link, so several steps were verified via direct navigation to the same href and via the network log rather than a first-hand click-through; the actual on-device download/install confirmation dialog could not be observed.
